# 出包与发布标准流程（FPSGame-Y1）

> **给 AI 的调用约定**：用户提出出包/发布相关需求时，按顺序做：
> 1. 先读本文件；
> 2. 判断属于「流程 A（只改服务端）」还是「流程 B（改了同步相关，客户端也要重出）」；
> 3. 明确告知用户本次属于哪种、需不需要重出客户端；
> 4. 给出可照抄的命令，最后按第 7 节验收。
> 文档与脚本不一致时，以脚本实际行为为准，并回来更新本文件。

## 2. 本地测试与快速迭代（优先看这一节）

**别每改一行就出双端包。** 大部分改动在编辑器里就能验证完，秒级生效。

### 2.1 编辑器工具：Tools → FPSGame-Y1

一个面板（**Ctrl+Shift+B**）覆盖四件事：

| 功能 | 位置 | 输出 / 行为 |
|---|---|---|
| 客户端打包 | 面板按钮 / 菜单 `打包客户端 (Windows)`（**Ctrl+Shift+C**） | `Build\WindowsClient\FPSGame-Y1.exe`（StandaloneWindows64 / Player） |
| 服务端打包 | 面板按钮 / 菜单 `打包服务端 (Linux Server)`（**Ctrl+Shift+S**） | `Build\LinuxServer\FPSGame-Y1.x86_64`（StandaloneLinux64 / **Server** 子目标，Mono） |
| 双端同时出包 | 面板按钮 / 菜单 `双端同时出包`（**Ctrl+Shift+D**） | 先服务端、后客户端，自动切构建平台，一次点完 |
| 切换服务端地址 | 面板按钮 / 菜单 `切换到本地服务地址`、`切换到真实服务地址` | 直接改场景里 `NetworkManager.networkAddress`：本地 `127.0.0.1` / 真实 `43.142.103.57` |

工具会自动处理出包前的老坑：

- 检测本机残留的 `FPSGame-Y1` 进程并**一键结束**（避免 `另一个程序正在使用此文件`）；
- 检查 Build Settings 里场景列表非空；
- 切换平台后**补设 Standalone 子目标**（否则服务端会出成普通客户端 —— 这是最容易踩的坑）；
- 出包失败时把 `result / errors / warnings / 输出路径` 打进 Console。

> ⚠️ **地址切换后必须 Ctrl+S 保存场景**，否则出包时带的还是旧地址。
> 工具会提示，但不会替你保存（避免把其它未保存的改动一起写盘）。

### 2.2 本地测试的四条路（按提效幅度排序）

| 方式 | 怎么做 | 适合什么 |
|---|---|---|
| **编辑器内起服务端** | 直接在 Play 模式点 HUD 的 Host / Server，脚本改动 recompile 后 1~3 秒生效 | 服务端逻辑（AI、判定、生成）—— **完全不用出包** |
| **ParrelSync 双开编辑器** | 主编辑器 Host，克隆编辑器 Client | 验证「别人看不到我」「同步不对」这类问题，官方推荐做法 |
| **本地打包服务端** | Windows Server / Linux Server 出到本地，客户端连 `127.0.0.1` | 必须测打包产物、无编辑器环境时的行为 |
| **出包后再测** | 走上面的工具出包 + `deploy.ps1` | 真机验证、给玩家更新 |

### 2.3 不想重新出包就换地址：运行时覆盖

`NetworkAddressConfig` 已挂在 TestScene 的 NetworkManager 上，启动时按优先级覆盖地址：

```
1. 命令行      FPSGame-Y1.exe -serverAddr 127.0.0.1
2. 环境变量    FPSGAME_SERVER_ADDR=127.0.0.1
3. 配置文件    <persistentDataPath>\server_addr.txt
4. 都没有      → 用场景里 NetworkManager 的地址
```

所以**同一份包既能连本地也能连生产**：

```powershell
# 连本地服务端
.\Build\WindowsClient\FPSGame-Y1.exe -serverAddr 127.0.0.1

# 连腾讯云（不带参数就走场景地址）
.\Build\WindowsClient\FPSGame-Y1.exe
```

### 2.4 顺手提效

- 场景里 `editorAutoStart` 打开后，进 Play 自动起服务端，省掉每次手点 HUD；
- 排障期勾 Development Build，正式包记得取消；
- 只改服务端逻辑时**不要重出客户端**（见第 3、4 节的区别）。

## 3. 出包前的必做检查（不做这三条，最常见的失败都会撞上）

> 推荐直接用 **Tools → FPSGame-Y1** 面板出包：下面第 1、2、3 条它都会自动检查/处理。

1. **关掉本机所有正在运行的 `FPSGame-Y1.exe`**（客户端、Windows 服务端都算）——
   否则 Unity 报 `Copying the file failed: 另一个程序正在使用此文件`。
   面板里有「结束这些进程」按钮；手工做法：
   ```powershell
   Get-Process | Where-Object { $_.Path -like "E:\FPSGame_Y1\FPSGame-Y1\*" } | Select-Object Id, ProcessName, Path
   Get-Process | Where-Object { $_.Path -like "E:\FPSGame_Y1\FPSGame-Y1\*" } | Stop-Process -Force
   ```
2. **输出目录固定走面板/脚本**：面板已把客户端固定到 `Build\WindowsClient`、服务端固定到
   `Build\LinuxServer`，不再手点目录框（选错会把 Windows/Linux 产物混在一起）。
3. **确认场景列表**没被改：只有 `Scenes/TestScene`，序号 0（面板底部实时显示当前列表）。

## 4. 流程 A：只改了服务端逻辑（AI、判定、生成等）

客户端**不需要**重出，玩家无感。

```powershell
# ① Unity：Tools → FPSGame-Y1 → 「只出服务端（Linux Server）」
#    或菜单 Tools/FPSGame-Y1/打包服务端 (Linux Server)，快捷键 Ctrl+Shift+S
#    输出固定在 Build\LinuxServer（StandaloneLinux64 / Server 子目标）
# ② Windows PowerShell：
cd E:\FPSGame_Y1\FPSGame-Y1
.\Tools\deploy\deploy.ps1
```
若提示"在此系统上禁止运行脚本"：
```powershell
powershell -ExecutionPolicy Bypass -File .\Tools\deploy\deploy.ps1
```

脚本会自动：打包（排除 `*_s.debug`）→ 上传 → 解压到 `/opt/fpsgame-<时间戳>` →
切换软链 → `systemctl restart fpsgame` → 健康检查 → 只保留最近 5 个版本。

## 5. 流程 B：改了「同步相关」内容 → 服务端 + 客户端都要重出

以下改动属于同步相关，**客户端必须一起重出并让玩家更新**，否则新旧版本会不兼容：

- `[SyncVar]` / `SyncList` / `SyncDictionary` 的增删改
- `[Command]` / `[ClientRpc]` / `[TargetRpc]` 的签名或行为
- `NetworkBehaviour` 的字段、`OnSerialize`/`OnDeserialize`
- Prefab 上的网络组件结构（NetworkIdentity、NetworkTransform、NetworkAnimator…）
- 玩家 Prefab 本身（Mirror 的 assetId 会变）

不兼容的表现：连不上、进场景后看不到别人、报 spawn / assetId 相关错误。

步骤：
1. 服务端 + 客户端：直接用 **Tools → FPSGame-Y1 → 「双端同时出包（服务端 → 客户端）」**
   （快捷键 **Ctrl+Shift+D**），一次点完并自动切平台；
   也可以分开出：`打包服务端 (Linux Server)` + `打包客户端 (Windows)`。
2. 分发 `Build\WindowsClient\` 下的客户端，并按第 7 节验收。

## 6. 流程 C：回滚到上一版

```powershell
.\Tools\deploy\deploy.ps1 -Rollback
```
服务器上确认：
```bash
ls -1dt /opt/fpsgame-*          # 版本目录，最新在最上
readlink -f /opt/fpsgame        # 当前指向
systemctl is-active fpsgame
ss -lunp | grep 7777
```

## 7. 每次发布后的验收清单

- [ ] `systemctl is-active fpsgame` 输出 `active`
- [ ] `ss -lunp | grep 7777` 有监听（`UNCONN ... *:7777`）
- [ ] 日志末尾有 `Server listening on port 7777`，**没有异常堆栈**
      （Development Build 会给每条 `Debug.Log` 附调用栈，属正常现象）
- [ ] 客户端点 **Client** 能进场景，能看到对方移动/旋转
- [ ] 杀掉一个客户端，服务端不崩、另一个客户端不受影响
- [ ] `.\Tools\deploy\deploy.ps1 -Rollback` 可用（版本目录已生成）

## 8. 故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| Build 报 `另一个程序正在使用此文件` | 旧客户端/服务端还在跑 | 用 Tools → FPSGame-Y1 面板一键结束进程，或按第 3 节关进程后重 Build |
| `构建目录不存在` / 找不到 `*.x86_64` | 输出目录选错 / 平台选错 | 用 `-BuildDir "实际路径"`；确认平台是 Linux Server |
| 客户端连不上 | 服务端没起 / 防火墙 / 端口 | 依次查 `systemctl is-active fpsgame` → `ss -lunp \| grep 7777` → 控制台防火墙 UDP 7777 |
| 日志 `address already in use` | 有手动前台跑的进程占着 7777 | `ps -ef \| grep FPSGame` → `sudo kill <pid>` → `sudo systemctl restart fpsgame` |
| 服务反复重启 | 缺 `_Data` 目录或端口被占 | `tail -n 50 /var/log/fpsgame/server.log` |
| `.ps1` 报语法错、中文乱码 | Windows PowerShell 5.1 按 GBK 解码 `.ps1` | **保持 `deploy.ps1` 纯 ASCII**（注释/提示都用英文） |
| 远端中文提示乱码 | 控制台按 GBK 解码 UTF-8 | 已在脚本里设 `[Console]::OutputEncoding = UTF8` |
| 改了同步代码后老客户端异常 | 客户端未同步更新 | 走流程 B |
| 服务端进程"莫名消失" | 前台跑，会话断开被杀 | 一律用 systemd（已在用），不要前台跑 |
| 出的服务端包其实是普通客户端 | 只切了平台没设 Standalone 子目标 | 用 Tools → FPSGame-Y1 面板出包（会自动补设 Server 子目标） |
| 客户端连不上，但服务端看着正常 | 场景地址还是旧的 / 忘了 Ctrl+S | 面板切到真实地址后 **Ctrl+S 保存场景**再出包；或启动时加 `-serverAddr` |
| 同一次会话里想连两台不同服务器 | 不想为换地址重新出包 | 出包后按 2.3 用 `-serverAddr` / 环境变量 / `server_addr.txt` 覆盖 |

## 9. 硬性规则（不要违反）

1. 构建产物**永远不要放进 `Assets\`**（Unity 会去导入它们）；统一放项目根的 `Build\` 下。
2. **不要把 `G1.pem` 提交进 git**（`.gitignore` 已排除 `*.pem`、`*.ppk`、`Build/`、`ClientDemo*/`、`ServerDemo/`）。
3. **不要手动 `scp` 覆盖 `/opt/fpsgame`** —— 它是软链，直接覆盖会写进旧版本目录里。一律走 `deploy.ps1`。
4. **不要直接改服务器上的 `/etc/systemd/system/fpsgame.service`** —— 下次 `-InstallService` 会覆盖它。
   要改就改仓库里的 `Tools/deploy/fpsgame.service`，然后：
   ```powershell
   .\Tools\deploy\deploy.ps1 -InstallService
   ```
5. 服务端不要放在 `/tmp`（系统会清理、重启会丢）；正式位置就是 `/opt/fpsgame-<时间戳>`。
6. 出正式包时取消 **Development Build**（日志更干净、性能正常）；排障期可以勾上。
7. **切换服务端地址后一定要 Ctrl+S 保存场景** —— 地址是场景数据，不保存就不会进包。
   出包前用面板的「先切到：本地/真实」可以让工具替你切，但场景仍需你保存一次。
8. 服务端地址**不要写死在代码里**；要临时改地址就用 `NetworkAddressConfig` 的三种运行时覆盖方式（见 2.3）。

## 10. 换新机器 / 重装系统时的环境准备（踩过的坑）

**A. Unity 模块**
需要：`Linux Server`（服务端）、`Windows Server`（本机自测）。
本项目只做 PC 端，**不需要** Android / iOS / WebGL 等移动端模块。

⚠️ **中国 CDN 缺少这两个 Server 模块的安装包**，Hub 里点会立刻 404（`NoSuchKey`）。解决办法：
从国际 CDN 直接下载安装器，再静默安装到编辑器目录：

```
https://download.unity3d.com/download_unity/bbb010bdb8a3/TargetSupportInstaller/UnitySetup-Linux-Server-Support-for-Editor-6000.3.6f1.exe
https://download.unity3d.com/download_unity/bbb010bdb8a3/TargetSupportInstaller/UnitySetup-Windows-Server-Support-for-Editor-6000.3.6f1.exe
```
```cmd
UnitySetup-Linux-Server-Support-for-Editor-6000.3.6f1.exe /S /D=D:\Class_Unity\6000.3.6f1
```
（`/D=` 必须是最后一个参数、路径不加引号；安装前关掉 Unity 编辑器）

**B. 服务器**
```bash
sudo useradd -r -g game -s /usr/sbin/nologin game
sudo mkdir -p /var/log/fpsgame && sudo chown game:game /var/log/fpsgame
```
首次发布会自动迁移已存在的 `/opt/fpsgame` 目录，并安装 systemd 单元：
```powershell
.\Tools\deploy\deploy.ps1 -InstallService
```

**C. 本地 SSH**
```powershell
icacls "$env:USERPROFILE\.ssh\G1.pem" /inheritance:r /grant:r "$($env:USERNAME):(R)"
ssh -i "$env:USERPROFILE\.ssh\G1.pem" ubuntu@43.142.103.57 'sudo -n true && echo SUDO-NOPASSWD-OK || echo NEEDS-PASSWORD'
```
`ubuntu` 需要免密 sudo（腾讯云镜像默认满足），否则 `deploy.ps1` 的远端步骤会失败。
